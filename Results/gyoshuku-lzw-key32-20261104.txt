LZW dictionary key layout (2026-11-04)

Candidate
- Keep the existing UnsafeMutablePointer<UInt64> linear-probe dictionary and hash/probe order.
- Change each entry from key << 16 | code to code << 48 | key. This lets the probe compare UInt32(truncatingIfNeeded: entry) directly instead of shifting every loaded entry right by 16.
- No compressed-output or API change is intended. Key values use at most 24 bits and codes fit in 16 bits.

Benchmark
- New opt-in LZWStreamEncoderBenchmarkTests, documented in Tests/README.md.
- 4 MiB fixed text, /usr/lib/dyld, and 4 MiB fixed-seed random input; maxbits 12 and 16.
- Every run compares the encoded bytes with the independent ReferenceLZWStreamEncoder and with earlier iterations.
- Mac mini baseline is a saved pre-change XCTest bundle. M4 Max baseline is built separately from tracked sources, whose LZW source SHA-256 matches HEAD.
- XCTest runner alternates baseline and candidate three times each, with ten inner repetitions. Values below are medians of each run's best time in seconds. Raw timings are retained because the host load caused visible frequency variation.
